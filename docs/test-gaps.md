# Test gaps

Purpose and audience: this is the working list of tests that are missing or weak for the work built on 2026-11-18 and 2026-11-19: the staff and customer Zalo Mini Apps, loyalty (ledger, matching, redemptions, phone privacy, erasure), the iPOS till rails (voucher callback, code pools, rail recognition), the OA menu and enrolment, member notifications and the member share per shift. It is for the builders and testers who write the next tests and for the reviewer who checks that a gap is closed. The [test plan](test-plan.md) holds the strategy, the ISTQB mapping ([section 2.14](test-plan.md#214-istqb-alignment)) and the product risk register this list draws its priorities from ([section 2.15](test-plan.md#215-product-risks-of-tracks-b-and-c)).

## 1. How to read this list

The list was drawn up on 2026-11-19 between 21:35 and 21:50 from the repository at `67fc697` with the uncommitted work of the other agents in the working tree (pgTAP files 115 to 135 among it, written by the testing agents that evening). Other agents were adding security, regression, customer messaging and server tests at the same time, so a gap may already be closing; check the file named under "Where" before starting one.

- **ID** `G-nn` is stable. A closed gap keeps its row, with "closed by `<file>`" in the "Missing or weak" cell and the commit.
- **Level** uses the ISTQB test levels of the [test plan, section 2.14](test-plan.md#214-istqb-alignment): component, component integration (CI-int), system integration (SI), system, acceptance.
- **Type** is functional, non-functional (performance, security, usability, accessibility, portability, reliability) or change-related (confirmation, regression).
- **Risk** names the product risk `PR-nn` of the [test plan, section 2.15](test-plan.md#215-product-risks-of-tracks-b-and-c).
- **Priority** follows the risk level: P1 for a high risk, P2 for a medium one, P3 for a low one. A gap that only strengthens a test that already exists at the same level drops one step; a gap that leaves a high risk without any test at its level stays P1.
- **Test idea** gives the technique, the inputs and the expected result. Phones are synthetic, in local form (`0900000000` to `0900000999`); tenants are fixture tenants that the test creates and removes ([test plan, section 4.3](test-plan.md#43-fixture-tenants)).
- **Where** is the file to extend or the new file proposed, with the suite prefix of [the test plan, section 1.5](test-plan.md#15-conventions).
